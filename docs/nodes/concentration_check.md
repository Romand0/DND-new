# concentration_check - 专注检定

## 功能概述

专注检定节点用于施法者进行专注豁免，检定体质属性对抗DC 10或伤害半数。这是处理持续法术专注维持的关键节点，确保施法者能够维持法术效果。

## 状态
- ✅ **当前**：主要使用的专注检定节点
- 🔄 **重要性**：持续法术流程的核心节点

## 配置项

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `dc` | template | 否 | "10" | 专注检定DC |
| `damageHalf` | boolean | 否 | false | 伤害半数作为DC |
| `autoFail` | boolean | 否 | false | 是否自动失败 |
| `autoSucceed` | boolean | 否 | false | 是否自动成功 |

## 详细配置说明

### dc - 专注检定DC
- **类型**：模板变量
- **必填**：否
- **默认值**：`"10"`
- **说明**：专注检定的难度等级
- **规则**：根据D&D 5e规则，DC为10或伤害半数（取较高值）
- **示例**：
  - 固定值：`"10"`
  - 模板变量：`"${lastDamage / 2}"`
  - 计算表达式：`"Math.max(10, lastDamage / 2)"`

### damageHalf - 伤害半数作为DC
- **类型**：布尔值
- **必填**：否
- **默认值**：`false`
- **说明**：是否使用受到伤害的一半作为DC
- **规则**：D&D 5e规则中，专注检定DC = max(10, 受到伤害的一半)
- **用途**：用于处理受到伤害时的专注检定

### autoFail - 自动失败
- **类型**：布尔值
- **必填**：否
- **默认值**：`false`
- **说明**：是否自动检定失败
- **用途**：用于某些特殊情况下强制失去专注

### autoSucceed - 自动成功
- **类型**：布尔值
- **必填**：否
- **默认值**：`false`
- **说明**：是否自动检定成功
- **用途**：用于某些特殊情况下保持专注

## 执行逻辑

### 1. 参数验证
- 检查 `dc` 参数的有效性
- 验证 `autoFail` 和 `autoSucceed` 不能同时为true
- 确认施法者存在且可以维持专注

### 2. DC计算
- **基础DC**：默认DC为10
- **伤害DC**：如果配置了 `damageHalf`，计算伤害的一半
- **最终DC**：取基础DC和伤害DC的较大值

### 3. 自动检定
- **自动失败**：如果 `autoFail` 为true，直接返回失败结果
- **自动成功**：如果 `autoSucceed` 为true，直接返回成功结果

### 4. 体质检定
- 获取施法者的体质属性值
- 计算体质修正值（体质值 // 2 - 5）
- 调用 `diceService.ts` 进行d20骰子投掷
- 计算总检定值（骰子结果 + 体质修正）

### 5. 结果判定
- 比较总检定值与DC值
- 判断是否维持专注
- 如果检定失败，标记为失去专注

### 6. 状态更新
- 更新施法者的专注状态
- 记录检定结果
- 生成结果消息

## 故障排除

### 常见问题

**问题1：DC计算错误**
- **原因**：DC值计算有误，特别是伤害半数的情况
- **解决**：检查DC计算逻辑，确保符合D&D 5e规则

**问题2：体质修正计算错误**
- **原因**：体质修正值计算错误
- **解决**：检查体质修正计算公式（体质值 // 2 - 5）

**问题3：专注状态更新失败**
- **原因**：专注状态更新逻辑有误
- **解决**：检查专注状态的更新逻辑，确保状态一致性

**问题4：模板变量解析失败**
- **原因**：`${lastDamage}` 等变量无法解析
- **解决**：检查变量名称是否正确，确保相关数据已加载

## 规则说明

### D&D 5e 专注规则
- **专注检定**：每个回合开始时进行体质检定
- **DC计算**：DC = max(10, 受到伤害的一半)
- **失去专注**：检定失败时失去专注
- **维持专注**：检定成功时维持专注
- **自动维持**：某些法术无需专注（如静电场）

### 专注的重要性
- **持续法术**：专注是维持持续法术的必要条件
- **法术效果**：失去专注会导致法术效果终止
- **战略选择**：专注管理是重要的战略选择
- **资源管理**：专注是重要的游戏资源
