# 三宝书图鉴种子硬编码进仓库 — 需求

## 引言

把《玩家手册 2014》《城主指南 2014》《怪物图鉴 2014》的图鉴资料（装备库、角色选项、怪物图鉴）硬编码进仓库作为基线种子，开箱即用、离线可用、首屏轻量。法术库流程相对独立，本次保持原状。

现状问题：

1. 装备库仅 18 条基础种子内联在 `src/data/equipments.json`；252 条魔法物品游离在 `public/magic-items-import.json`，需管理员在数据管理页手动导入 D1 才可用
2. 怪物图鉴 421 条（560KB 原始 / 148KB gzip）静态打进主 bundle，计入首屏成本
3. 角色选项 84 条已按需 chunk，但缓存策略与其它库不统一
4. 三个库的缓存与云端合并策略各不相同，种子版本升级无法可靠刷新已缓存用户

## 术语表

- **图鉴种子（Seed）**：随仓库发布、编译或打包进静态资产的官方条目集合，随 Git 提交演进
- **覆盖层（Overlay）**：云端 D1 中同 id 覆盖种子字段的用户编辑行
- **墓碑（Tombstone）**：标记种子条目被用户删除的云端记录
- **懒加载资产（Lazy Asset）**：放在 `public/seed/` 下、由前端运行时 fetch 的静态 JSON
- **基线合并（Baseline Merge）**：种子 ∪ 云端覆盖 − 墓碑 的三方合并
- **规则书集（Rulebook Scope）**：团组配置的可见出版物白名单，`campaigns.rulebooks`
- **出版物条目**：`campaign_id IS NULL` 的全局共享条目
- **种子只读**：UI 不提供种子条目的编辑与删除入口，内容变更随仓库发布

## 需求

### 需求 1：种子数据随仓库发布

**用户故事**：作为站长，我希望三宝书图鉴资料随仓库发布，以便部署后开箱即用、离线可查。

#### 验收标准

1. 仓库 SHALL 在 `public/seed/` 下提供装备、怪物、角色选项三份种子 JSON 资产。
2. 装备种子 SHALL 同时包含玩家手册基础装备与城主指南魔法物品，并保持原有字段结构。
3. 角色选项种子 SHALL 保持种族、亚种、背景、职业、子职业五类完整。
4. 每份种子文件 SHALL 携带种子版本号字段，用于客户端判断缓存是否过期。
5. WHEN 种子源数据更新并提交仓库，THE 种子版本号 SHALL 随之递增。

### 需求 2：种子懒加载以控制首屏成本

**用户故事**：作为移动端用户，我希望首屏加载不受图鉴数据影响，以便弱网下快速进入应用。

#### 验收标准

1. 怪物种子 SHALL 从主 bundle 移出，改为访问怪物页或怪物选择器时按需加载。
2. 角色选项种子 SHALL 保持按需加载。
3. WHEN 用户停留在不涉及图鉴的页面，THE 系统 SHALL 不请求任何图鉴种子资产。
4. WHEN 图鉴数据加载完成，THE 系统 SHALL 通过订阅通知已挂载视图刷新。

### 需求 3：基线合并策略

**用户故事**：作为站长，我希望云端只存用户增改，以便种子升级与用户自定义互不干扰。

#### 验收标准

1. 客户端 SHALL 按「种子 ∪ 云端覆盖 − 墓碑」计算图鉴最终视图。
2. WHEN 云端存在与种子同 id 的覆盖行，THE 云端覆盖行 SHALL 覆盖同 id 种子条目。
3. WHILE 云端覆盖行存在，THE 种子条目 SHALL 保持可见且呈现覆盖后的字段。
4. 客户端 SHALL 保留用户自建条目（id 不在种子集内）与云端原有条目。
5. WHEN 种子版本号高于本地缓存记录的版本号，THE 系统 SHALL 丢弃本地缓存的种子副本来重新加载。

### 需求 4：种子条目只读

**用户故事**：作为站长，我希望种子内容以仓库为唯一真源，以便版本可回溯、多部署一致。

#### 验收标准

1. WHILE 条目来源为种子，THE 界面 SHALL 隐藏编辑与删除入口。
2. WHILE 条目来源为云端自定义，THE 界面 SHALL 提供编辑与删除入口。
3. IF 用户尝试通过批量操作修改种子条目，THE 系统 SHALL 跳过该条目并提示。
4. 种子条目的内容变更 SHALL 通过修改仓库种子文件并重新发布完成。

### 需求 5：规则书集可见性保持

**用户故事**：作为团组 DM，我希望图鉴可见性仍按团组规则书集过滤，以便只展示本桌启用的资料。

#### 验收标准

1. 种子条目 SHALL 携带来源书名，并遵循现有规则书集过滤语义。
2. WHEN 团组规则书集包含某书名，THE 该书名下的种子条目 SHALL 可见。
3. WHEN 团组规则书集不包含某书名，THE 该书名下的种子条目 SHALL 不可见。
4. 访客与无团组用户 SHALL 仅看到出版物种子条目。

### 需求 6：云端存量出版物清理

**用户故事**：作为站长，我希望云端数据库不再保留整份图鉴副本，以便数据一致、请求体变小。

#### 验收标准

1. 系统 SHALL 提供一次性清理操作，删除四库中 `campaign_id IS NULL` 的出版物行。
2. WHEN 清理执行完成，THE 云端 SHALL 仅保留用户自定义条目与覆盖行。
3. IF 清理后客户端离线且无本地缓存，THE 系统 SHALL 回退到仓库种子完整可用。
4. 清理操作 SHALL 支持先预览受影响行数再执行。

### 需求 7：种子导出与更新流程

**用户故事**：作为站长，我希望从现有云端数据生成种子文件，以便把完整图鉴带进仓库。

#### 验收标准

1. 数据管理页 SHALL 提供导出按钮，一次性下载三库当前全量数据为单个 JSON 文件。
2. 导出文件 SHALL 保留条目原始字段，不裁剪魔法物品等扩展字段。
3. 系统 SHALL 提供离线转换脚本，把导出文件拆分为 `public/seed/` 下三份种子文件并写入版本号。
4. WHEN 转换脚本运行完成，THE 脚本 SHALL 输出各库条目数与体积统计。
5. 转换脚本 SHALL 校验必填字段，并对异常条目输出告警清单。

### 需求 8：法术库保持原状

**用户故事**：作为站长，我希望法术库维持现有流程，以便本次改动范围收敛。

#### 验收标准

1. 本次改动 SHALL NOT 修改法术库的数据来源与加载链路。
2. 法术库既有的 `public/spells-fallback.json` 托底机制 SHALL 保持可用。

## 决策记录

| 决策点 | 结论 |
|--------|------|
| D1 云端定位 | 静态种子为基线，云端只存用户增改 |
| 装备库范围 | 复用现有云端非魔法装备 + 已有 252 条魔法物品 |
| 怪物加载方式 | 改懒加载静态资产 |
| 云端到仓库导出 | 数据管理页按钮下载 + 本地离线转换脚本 |
| 种子可编辑性 | 种子只读，改动进仓库 |
| 存量出版物 | 一次性清理 `campaign_id IS NULL` 行 |
