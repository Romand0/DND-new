# 法术流程流水线

> 编排层 skill：把「不全书搜索」（检索）与「流程生成器」（建模）串成单入口流水线。本文档承载阶段流转、阶段间数据契约、阻断点、异常分支与**执行预算纪律**（§0.4 / §0.5）；机制细节一律按章节号引用另外两份 SKILL.md，且**引用即定点读取，禁止通读**。

---

## 版块 0：定位与前提

### 0.1 三文档分工

| 文档 | 职责 | 本流水线的使用方式 |
|------|------|------------------|
| 本文档 | 阶段编排、数据契约、阻断与恢复 | 每次任务的主索引，按版块 1 阶段表顺序执行 |
| `skills/不全书搜索/SKILL.md` | 双通道检索、GBK 处理、多书源裁决 | 阶段 1 的执行体 |
| `skills/流程生成器/SKILL.md` | 抽取归一化、节点/边建模、配置、自审、扩展、人机分工 | 阶段 3–7 的执行体 |

### 0.2 何时进流水线，何时单独用两个 skill

- 用户给出**法术名**且目的是「生成流程 / DSL / 节点图 / 控制台代码」→ 进流水线。
- 用户只想**查规则原文**（核对数值、看描述）→ 只用不全书搜索，走完即止。
- 用户**自己粘贴了法术文本**且只要生成流程 → 只用流程生成器（跳过流水线的检索阶段亦可，见 §1 阶段 0 分支）。
- 用户要生成的是**职业特性/怪物能力**流程 → 只用流程生成器（本流水线专做法术）。

### 0.3 前提检查

1. `/workspace/data/DND5e_chm` 存在；缺失时按不全书搜索「数据源」节 clone。
2. 流程生成器 §0.4「文档与代码差异表」已阅读——所有节点配置键名以该表右列为准。
3. 明确人机边界（流程生成器 §6.1）：agent 生产与自审，**入库与新节点类型实施必须人工批准**。

### 0.4 执行预算与阅读纪律（防冗余）

流水线的最大浪费来自「把规格书写成实现调研」：为一份 4 节点线性图通读三份 SKILL、逐条回源代码复核 key 名、深挖与当前法术无关的引擎细节，结果一个产物都没落。本节把这种损耗变成可判定的违规。

**阅读纪律**

1. **禁止通读 SKILL.md**。任何一份 SKILL 的取用方式是：`grep -n '^#\{2,3\} '` 拿章节表 → 按阶段表指向的章节号 `read` 定点读取，单次 ≤ 80 行。任务结束时对每份 SKILL 的累计读取超过 200 行即视为超预算，必须在交付消息里说明原因。
2. **先查章节表，再查正文**。阶段表每一行的「动作」列已给出章节号，这些章节号就是本次任务需要读的全部内容。
3. **不读与本任务无关的章节**：修改模式、扩展清单、模板全文、维护规则在对应场景出现前不读。

**权威信任分级（取代"全部重验"）**

| 级别 | 内容 | 处理方式 |
|------|------|---------|
| 直接采信 | 流程生成器 §0.4 键名差异表、§3.1 配置契约、§2.3 拓扑配方、§2.4 图规则、§5.1 门 A 判据 | 照写，**不打开源码复核** |
| 抽样确认 | 本流程实际用到的节点在 `flowCompiler.ts` 中的关键分支（如 healing 上限钳制、dc 留空取值） | 每节点 ≤ 1 次定点 grep，命中即停 |
| 禁止复核 | 未用到的节点实现、UI 组件、落地副作用、数据结构扩展史 | 不查；相关问题直接进「待确认项」 |

`src/` 源码复核总额上限 **6 次工具调用**。超出即停止侦查，把剩余疑问按 §0.5 降级为待确认项。

**产出优先**

1. 阶段 3 结束必须已产出机制规格表（可先留空字段），阶段 5 结束必须已产出完整 JSON。任何侦查都发生在这些产物落地之后。
2. 中途发现需要额外侦查时，先输出当前产物 + 一句「需要确认 X」，再继续；不允许连续 10 次以上工具调用而无任何产物落地。
3. 待确认项属于交付物的一部分，它的用途是让人在评审时定夺，无需在交付前查清。节点表达不了的机制（施法属性加值、升环环位、生物类型过滤）一律写进待确认表，禁止为它预先设计或实现引擎扩展。

### 0.5 任务复杂度分级与快车道

阶段 0 完成入口判定后立即定级，分级决定允许的侦查深度：

| 级别 | 判据 | 拓扑 | 允许动作 |
|------|------|------|---------|
| 简单 | 无判定、无分支、无缩放、无状态、无区域；单效果节点 | ≤ 5 节点线性 | 只读 §2.3 对应配方 + §3.1 对应节点配置；源码复核 0 次；工具调用目标 ≤ 12 |
| 中 | 含单一判定或状态/奖惩/区域节点 | 6–10 节点 | 抽样确认所用节点；源码复核 ≤ 3 次 |
| 复杂 | 多段分流、缩放分档、连锁条件 | > 10 节点 | 按 §0.4 上限执行，允许提出扩展契约 |

定级结果写入自审报告首行。定级偏低的代价只是把问题移入待确认表；定级偏高的代价是成倍额度浪费，因此**默认向下定级**，遇到反例再升。

**反模式清单**（出现任一即为流程违规）：

- 通读三份 SKILL.md 全文
- 重验流程生成器 §0.4 差异表已明示的键名（用 grep 回源码确认某个配置键是否真被读取）
- 为「代码其实还没实现」的能力深挖实现细节（升环环位输入框、目标生物类型过滤、UI 摘要拼接）
- 在一份 ≤ 5 节点的线性图上花超过 12 次工具调用
- 把待确认项当成阻断项，先行设计代码扩展

## 版块 1：阶段总图

每次任务按此表顺序执行。每个阶段标注：输入 → 动作（引用）→ 输出 → 失败分支（对应版块 3 异常表）。

| # | 阶段 | 输入 | 动作 | 输出 | 失败分支 |
|---|------|------|------|------|---------|
| 0 | 输入确认 | 用户消息 | 区分三种入口：仅法术名 / 已有原文文本 / 修改已入库流程（转流程生成器修改模式，数值核对仍走本流水线阶段 1） | 入口判定 | E0 入口歧义 |
| 1 | 原文获取 | 法术名 | 执行不全书搜索标准查询流程，**强制原文模式**；多书源命中时并列展示请用户裁决（默认 2014 PHB） | 法术原文包（模板 `templates/spell-packet.md`） | E1–E4 |
| 2 | 库内查重 | 法术原文包 | 查 `spellStore`（`getByName` 本地；`api.fetchSpells` 云端）：命中 → 记录 spellId；未命中 → **阻断**（见版块 2.2） | spellId 或 BLOCKED(UNBOUND) | E5 |
| 3 | 机制规格 | 法术原文包 | 按流程生成器 §1.1 抽取清单逐项抽取，§1.2 归一化，缺失记待确认；流程 description 按 §2.1.1 公式生成 | 机制规格表 | E6 |
| 4 | 节点图建模 | 机制规格表 | 按 §2.3 拓扑配方选型、§2.4 图规则连边、§2.5 命名；超纲机制按版块 4 旁路 | 节点边清单 | E7 |
| 5 | 配置 | 节点边清单 | 按流程生成器 §3.1–3.4 填节点配置、边属性、坐标、流程级字段 | FlowDefinition JSON 草稿 | — |
| 6 | 自审 | FlowDefinition 草稿 | 执行流程生成器 §5 门 A–D，产出含门 D 运行支撑标注表的报告 | 自审报告 | E8 |
| 7 | 交接 | 全部产物 | 按流程生成器 §6.3 四段固定格式输出，附加 spellId 绑定信息段（版块 5） | 交接消息 | — |

**阶段 0 附带动作**：完成入口判定后立即按 §0.5 定级，定级结果决定后续阶段的侦查深度。**阶段 3 与阶段 5 是产物检查点**——到达这两个阶段时若还没有可展示的规格表 / JSON，说明侦查已越界，立刻停止侦查先落地产物。

**取用即定点**：表中「动作」列的每个章节号就是该阶段需要读取的全部内容，按 §0.4 的 `grep 章节表 → read 定点` 方式取用，禁止通读被引用文档。

## 版块 2：阶段契约

### 2.1 法术原文包（阶段 1 → 3 的传递产物）

模板：`templates/spell-packet.md`。字段对齐流程生成器 §1.1 抽取清单，附加三项流水线特有信息：

- **书源与文件路径**：保留原文引用的可回溯性（原文模式逐字保留）。
- **spellId 状态**：已入库的 id 或 `UNBOUND`。
- **待裁决项**：多书源差异、译名歧义；无则写「无」。

原文包是跨阶段与跨会话的最小恢复单元：任何时刻中断，从最近一次原文包/规格表产物即可重建现场。

### 2.2 阻断点：法术未入库（E5）

规则（需求规格 Requirement 2）：

1. `spellStore.getByName` 本地与云端法术库均未命中该法术 → 流水线**停在阶段 2**。
2. 已产出的原文包保留并向用户展示，同时给出入库前置步骤：
   - 首选：DataManagement 页「从 5E 不全书导入_法术」批量导入；
   - 或 SpellEditor 手动录入。
3. **禁止**在 `spellId === UNBOUND` 状态下产出 FlowDefinition（`cast_start` 运行时依赖法术库元数据，未绑定流程无运行意义）。
4. 用户确认法术已入库后，**从阶段 3 恢复**：重新查重拿 spellId，原文包补录 id，继续建模。

### 2.3 超纲机制旁路（阶段 4 内）

判定顺序（承接流程生成器 §1.3 / §4.1）：

1. 机制可由 9 种节点 + 6 种触发边表达 → 直接建模。
2. 机制超纲但为**一次性/特异**（如某法术独有的奇门效果）→ `custom` 节点占位，自审报告注明「图已表达，运行未实现」。
3. 机制超纲且为**可泛化原子**（多本/多法术复用，如强制位移、区域持续地形）→ 产出节点类型契约（模板：流程生成器 `templates/new-node-type-contract.md`），**等待人工批准**；未批准期间保持 `custom` 占位继续走完阶段 5–7（JSON 可先行交付，报告标注扩展待办）。

## 版块 4：扩展旁路的流水线纪律

流程生成器 §4 的扩展改动清单全部适用，流水线视角追加三条纪律：

1. **契约先行**：新节点类型契约未经人工批准，一律保持 `custom` 占位；禁止「顺手」改 `src/types/flow.ts`。
2. **批准后实施**：人工批准契约 → 按流程生成器 §4.2/4.3 改动清单实施 → `npx tsc --noEmit` 与 `npm run build` 通过 → 编辑器验证可拖出/可配/可存/可发布。
3. **兼容性**：新版本只增键不改键；已发布流程语义稳定（流程生成器 §4.5）。

## 版块 5：交接产物（在流程生成器 §6.3 四段之上追加）

四段固定格式不变（机制规格表 / FlowDefinition JSON / 自审报告 / 待人工操作），在「待人工操作」段之前插入**绑定信息段**：

```markdown
## 绑定信息
- 法术：<中文名>｜<English>
- spellId：<id>（本地/云端查得）
- 书源：玩家手册 2014
- 若为更新模式：现有流程 id 与版本号（FlowConsole 更新模式匹配键）
```

明确禁止（继承流程生成器 §6.4）：调用任何写接口、直接入库、未经指示执行删除模式、把静态校验通过表述为「机制已验证正确」。

**预算复盘段**（固定在交接消息末尾，一句话即可）：

```markdown
## 预算复盘
- 复杂度定级：简单 / 中 / 复杂
- 工具调用：<总数>（源码复核 <n> 次，上限 6）
- SKILL 累计读取：<行数>（单份上限 200 行）
- 越界说明：无 / <原因>
```

超限而未在产物中体现的部分，视为未完成交付。这份复盘的作用是让越界可见——它是自我约束的度量，不是报告装饰。

## 版块 6：维护规则（弱耦合引用）

1. 本文档对两个既有 skill 的引用一律带章节号（如「流程生成器 §3.1」）；被引用文档章节重排时，只需更新本文档各表中的引用列。
2. 本文档正文不得出现：检索命令、节点配置键名、抽取清单明细——这些细节的单一事实源在两个被引用 skill 中。
3. 两个既有 skill 的出口提示（不全书搜索末尾「出口路由」、流程生成器 §0.1 追加项）是它们指向本文档的唯一接缝；流水线规则变更时同步检查这两处措辞。
4. **执行预算纪律（§0.4 / §0.5）的单一事实源是本文档**。被引用的两份 SKILL 只在各自的入口处挂一句「受流水线 §0.4/§0.5 约束」的短引用，不复制预算数值；调整阈值（源码复核次数、工具调用上限、SKILL 读取行数）只改本文档。
