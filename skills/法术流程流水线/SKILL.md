# 法术流程流水线

> 编排层 skill：把「不全书搜索」（检索）与「流程生成器」（建模）串成单入口流水线。本文档只承载阶段流转、阶段间数据契约、阻断点与异常分支；机制细节一律按章节号引用另外两份 SKILL.md。

---

## 版块 0：定位与前提

### 0.1 三文档分工

| 文档 | 职责 | 本流水线的使用方式 |
|------|------|------------------|
| 本文档 | 阶段编排、数据契约、阻断与恢复 | 每次任务的主索引，按版块 1 阶段表顺序执行 |
| `skills/不全书搜索/SKILL.md` | 双通道检索、GBK 处理、多书源裁决 | 阶段 1 的执行体 |
| `skills/流程生成器/SKILL.md` | 抽取归一化、节点/边建模、配置、自审、扩展、人机分工 | 阶段 3–7 的执行体 |

### 0.2 何时进流水线，何时单独用两个 skill

- 用户给出**法术名**且目的是「生成流程 / DSL / 节点图 / 控制台代码」→ 进流水线。
- 用户只想**查规则原文**（核对数值、看描述）→ 只用不全书搜索，走完即止。
- 用户**自己粘贴了法术文本**且只要生成流程 → 只用流程生成器（跳过流水线的检索阶段亦可，见 §1 阶段 0 分支）。
- 用户要生成的是**职业特性/怪物能力**流程 → 只用流程生成器（本流水线专做法术）。

### 0.3 前提检查

1. `/workspace/data/DND5e_chm` 存在；缺失时按不全书搜索「数据源」节 clone。
2. 流程生成器 §0.4「文档与代码差异表」已阅读——所有节点配置键名以该表右列为准。
3. 明确人机边界（流程生成器 §6.1）：agent 生产与自审，**入库与新节点类型实施必须人工批准**。

## 版块 2：阶段契约

### 2.1 法术原文包（阶段 1 → 3 的传递产物）

模板：`templates/spell-packet.md`。字段对齐流程生成器 §1.1 抽取清单，附加三项流水线特有信息：

- **书源与文件路径**：保留原文引用的可回溯性（原文模式逐字保留）。
- **spellId 状态**：已入库的 id 或 `UNBOUND`。
- **待裁决项**：多书源差异、译名歧义；无则写「无」。

原文包是跨阶段与跨会话的最小恢复单元：任何时刻中断，从最近一次原文包/规格表产物即可重建现场。

### 2.2 阻断点：法术未入库（E5）

规则（需求规格 Requirement 2）：

1. `spellStore.getByName` 本地与云端法术库均未命中该法术 → 流水线**停在阶段 2**。
2. 已产出的原文包保留并向用户展示，同时给出入库前置步骤：
   - 首选：DataManagement 页「从 5E 不全书导入_法术」批量导入；
   - 或 SpellEditor 手动录入。
3. **禁止**在 `spellId === UNBOUND` 状态下产出 FlowDefinition（`cast_start` 运行时依赖法术库元数据，未绑定流程无运行意义）。
4. 用户确认法术已入库后，**从阶段 3 恢复**：重新查重拿 spellId，原文包补录 id，继续建模。

### 2.3 超纲机制旁路（阶段 4 内）

判定顺序（承接流程生成器 §1.3 / §4.1）：

1. 机制可由 9 种节点 + 6 种触发边表达 → 直接建模。
2. 机制超纲但为**一次性/特异**（如某法术独有的奇门效果）→ `custom` 节点占位，自审报告注明「图已表达，运行未实现」。
3. 机制超纲且为**可泛化原子**（多本/多法术复用，如强制位移、区域持续地形）→ 产出节点类型契约（模板：流程生成器 `templates/new-node-type-contract.md`），**等待人工批准**；未批准期间保持 `custom` 占位继续走完阶段 5–7（JSON 可先行交付，报告标注扩展待办）。

## 版块 4：扩展旁路的流水线纪律

流程生成器 §4 的扩展改动清单全部适用，流水线视角追加三条纪律：

1. **契约先行**：新节点类型契约未经人工批准，一律保持 `custom` 占位；禁止「顺手」改 `src/types/flow.ts`。
2. **批准后实施**：人工批准契约 → 按流程生成器 §4.2/4.3 改动清单实施 → `npx tsc --noEmit` 与 `npm run build` 通过 → 编辑器验证可拖出/可配/可存/可发布。
3. **兼容性**：新版本只增键不改键；已发布流程语义稳定（流程生成器 §4.5）。

## 版块 5：交接产物（在流程生成器 §6.3 四段之上追加）

四段固定格式不变（机制规格表 / FlowDefinition JSON / 自审报告 / 待人工操作），在「待人工操作」段之前插入**绑定信息段**：

```markdown
## 绑定信息
- 法术：<中文名>｜<English>
- spellId：<id>（本地/云端查得）
- 书源：玩家手册 2014
- 若为更新模式：现有流程 id 与版本号（FlowConsole 更新模式匹配键）
```

明确禁止（继承流程生成器 §6.4）：调用任何写接口、直接入库、未经指示执行删除模式、把静态校验通过表述为「机制已验证正确」。

---

## 版块 6：维护规则（弱耦合引用）

1. 本文档对两个既有 skill 的引用一律带章节号（如「流程生成器 §3.1」）；被引用文档章节重排时，只需更新本文档各表中的引用列。
2. 本文档正文不得出现：检索命令、节点配置键名、抽取清单明细——这些细节的单一事实源在两个被引用 skill 中。
3. 两个既有 skill 的出口提示（不全书搜索末尾「出口路由」、流程生成器 §0.1 追加项）是它们指向本文档的唯一接缝；流水线规则变更时同步检查这两处措辞。
